# Multi-session plans

GitHub issues remain the lifecycle and ownership record. Add a plan here only
when work cannot be executed safely from one bounded issue description.

Name plans `<issue>-short-title.md` and include:

- linked issue and current owner;
- status and last-verified date/commit;
- objective, non-goals, and constraints;
- ordered steps with validation and rollback;
- decisions made and open questions;
- handoff and exact next action.

Re-verify code and external assumptions before executing an old plan. Archive or
delete completed implementation detail once its durable conclusions have been
promoted to normal docs or an ADR.
